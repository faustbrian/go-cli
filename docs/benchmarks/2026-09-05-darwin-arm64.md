## Equivalent command comparison

**Comparison class: common-denominator comparison.** Each framework consumes
the same allocation-free `tool deploy --force target` argv, selects a native
subcommand, resolves the same flag and positional input, performs one
validation and action, and renders the same bounded JSON result through a
complete-write check. See the [execution boundary](../../benchmarks/README.md#comparison-boundary)
before interpreting the values.

The cold timed region constructs a new framework application and invokes it
once in every benchmark iteration. The repeated timed region constructs the
application before the timer starts, then includes each complete reusable
invocation. Both regions include the framework's parsing, resolution,
validation, action, common result rendering, bound enforcement, and complete
write to `io.Discard`; neither includes lifecycle cleanup.

| Framework | Cold latency | Cold throughput | Cold bytes / allocations | Repeated latency | Repeated throughput | Repeated bytes / allocations |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `go-cli` | 2.925 µs ±34% | 342.1k/s ±26% | 5.293 KiB / 51 | 1.043 µs ±43% | 959.0k/s ±30% | 1.542 KiB / 21 |
| Cobra | 3.210 µs ±125% | 312.6k/s ±56% | 7.244 KiB / 72 | 1.508 µs ±143% | 663.2k/s ±59% | 1.621 KiB / 31 |
| `urfave/cli` | 4.513 µs ±62% | 221.6k/s ±38% | 8.276 KiB / 234 | 3.344 µs ±375% | 299.0k/s ±79% | 4.369 KiB / 183 |
| Kong | 20.28 µs ±48% | 49.46k/s ±33% | 22.31 KiB / 357 | 8.238 µs ±259% | 121.4k/s ±72% | 9.209 KiB / 187 |

All samples were retained. Material high deviations of at least 50% above the
median were:

- process 3: Cobra cold +55%; Cobra, `urfave/cli`, and Kong repeated +143%,
  +375%, and +259%; `flag` +235%
- process 4: every result except `go-cli` cold, ranging from `flag` at +234%
  to `go-cli` repeated at +934%; Cobra cold was 18.577 µs (+479%) and Cobra
  repeated was 10.468 µs (+594%)
- process 5: `urfave/cli` cold +62%
- process 8: `go-cli` cold +80% and Cobra cold +125%

The wide confidence intervals reflect those retained clusters. They make the
capture unsuitable for close cross-framework ranking; no speed ratio or
winner is claimed.

## Parsing floor

**Comparison class: raw baseline.** The standard `flag` package measured
22.60 ns/op ±234%, 44.26M invocations/s ±70%, with zero measured bytes and
allocations per operation. It has no command graph, validation/action
lifecycle, structured output, output bound, or repeated application state, so
it is not comparable with the command-framework table. Its statistical
summary and geomean are kept separate from the common-denominator comparison.

## Evidence and limitations

The in-window conformance run passed before sampling. It exercises exact
success, validation failure, structural usage failure, valid-invalid-valid
state isolation, output limit, incomplete writes on success and failure, and
the owned-parser differential through the same builders and runners used by
the benchmarks.

The capture used a coordinated slot but not an isolated benchmark host.
Scheduler activity, thermal state, frequency changes, and unrelated background
work can affect the results; the retained sample clusters show that material
interference occurred. The endpoint identity, all 90 expected benchmark rows,
and all ten process headers, `PASS` records, and package results were retained.
The capture workflow removed its task-owned caches before atomically publishing
the bundle.
